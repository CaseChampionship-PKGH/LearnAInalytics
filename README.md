## Введение

**TestAInspector** — система автоматического анализа результатов выполнения тестовых заданий с помощью групп ИИ-агентов. Проект разработан для Корпоративного университета Санкт-Петербурга и предназначен для методистов и разработчиков электронных курсов.

Основные возможности:
- Автоматическое сравнение ответов пользователей с эталоном.
- Выявление аномальных паттернов (массовые неправильные ответы, критические вопросы).
- Формирование структурированного отчёта с рекомендациями.
- Поддержка двух вариантов нейросетей: российских (YandexGPT) и зарубежных (DeepSeek / OpenRouter).
- Экспорт результатов в JSON и Excel с подсветкой отклонений.

## Архитектура и проектные решения

### Общая схема системы

Система построена на многослойной архитектуре **Onion / Hexagonal**, что обеспечивает модульность и масштабируемость.  
Верхнеуровневая диаграмма потоков данных:

```
[Пользователь] → (Blazor Web UI) → [HTTP API] → [Pipeline] → [Агенты LLM] → [Отчёт]
```

Основные модули:
- **API (ASP.NET Core Minimal API)** – принимает файлы, запускает конвейер анализа.
- **Pipeline** – оркестрирует этапы обработки: парсинг → валидация → батчинг → вызов ИИ → сбор статистики → генерация отчёта.
- **Parsing** – конвертирует входные JSON / CSV / ZIP в унифицированные модели.
- **Validation** – отсеивает записи с нулевым баллом, дубликаты, формирует справочник вопросов.
- **Analysis (вопрос-центричный батчинг)** – группирует ответы по вопросам, выполняет алгоритмический предотсев точных совпадений и пустых ответов, а затем вызывает ИИ-агента только для нечётких случаев.
- **Agent.Contracts** – интерфейсы `ILlmClient`, `IPromptProvider`, `IResponseParser`; фабрика `IAgentFactory`.
- **Агенты** – реализации для YandexGPT, DeepSeek / OpenRouter (совместимы с OpenAI API).
- **Reporting** – программная сборка `ReportData`, вызов ИИ-генератора рекомендаций, экспорт в Excel с условным форматированием.
- **Web UI (Blazor Server)** – одна интерактивная страница для загрузки данных и отображения результатов.

### Обоснование выбора технологий
- **.NET 8 / C#** – высокая производительность, строгая типизация, удобство работы с данными.
- **Blazor Server** – быстрая разработка интерактивного UI без JavaScript, компонентный подход.
- **Абстракции IDataParser, IAgent, IReportBuilder** – легко добавлять новые форматы и нейросети без изменения ядра.
- **Две группы агентов** – соответствие ТЗ; российская (YandexGPT) и зарубежная (OpenRouter/DeepSeek) реализованы через единый контракт.

## Принципы работы ИИ-агентов и промптов

### Конвейер вызова агента

1. **Подготовка батча**  
   Все ответы группируются по вопросу. Для каждого вопроса формируется `QuestionBatch`, содержащий:
   - Текст вопроса, правильный ответ, тип.
   - Список ответов пользователей с предварительным статусом:
     - `ExactMatch` – точное совпадение (после нормализации), не требует ИИ.
     - `Empty` – пустой ответ, не требует ИИ.
     - `NeedAnalysis` – требует анализа.

2. **Отправка промпта**  
   Для ответов с флагом `NeedAnalysis` вызывается `ITestAnalysisAgent.AnalyzeBatchAsync()`.  
   Промпт (формируется `IPromptProvider`):
   ```
   Ты — эксперт по проверке тестовых заданий.
   Дан вопрос, эталонный ответ и список ответов пользователей.
   Для каждого пользователя определи:
   - процент совпадения с эталоном (0-100)
   - вердикт: correct / partial / incorrect
   - краткое обоснование (1 предложение на русском)

   Вопрос: {текст}
   Правильный ответ: {эталон}
   Ответы пользователей:
   user_001: "ответ1"
   user_002: "ответ2"

   Верни ТОЛЬКО JSON без markdown-обёртки:
   {
     "results": [
       { "userId": "user_001", "similarityPercent": 85, "verdict": "correct", "comment": "..." }
     ]
   }
   ```
   Агент возвращает JSON, который парсится через `IResponseParser` (извлекает `AgentBatchResponse`).

3. **Объединение результатов**  
   Программные `ExactMatch` и `Empty` добавляются к ИИ-результатам, формируя полный `QuestionAnalysisResult`.

4. **Генерация рекомендаций**  
   После сбора всей статистики формируется `AnalysisDataForReport` и отправляется второму агенту `IReportAgent`:
   ```
   Ты — эксперт по анализу тестовых заданий.
   Тебе предоставлены агрегированные результаты проверки.
   Выяви критические вопросы (процент правильных ниже 50%) и дай рекомендации.
   Не изменяй предоставленную статистику, добавь поля criticalIssues и recommendations.
   Верни ТОЛЬКО JSON.
   ```
   Ответ парсится в `ReportData`.

## Сравнительный анализ российских и зарубежных нейросетей

| Критерий | YandexGPT Lite | через OpenRouter |
|----------|---------------|-----------------------------|
| **Точность сравнения** (по тестовой выборке из 10 вопросов) | 92% совпадений с экспертной оценкой | 95% |
| **Стабильность формата** | Иногда оборачивает JSON в пояснения | Стабильно чистый JSON |
| **Задержка (1 батч ~20 ответов)** | ~3-5 сек | ~2-4 сек |
| **Стоимость 1К токенов** | ~0,16 ₽ (вход) / ~0,64 ₽ (выход) | Бесплатно (бесплатный тир OpenRouter) |
| **Простота интеграции** | Требуется IAM-токен или API-ключ, folderId | Единый API-ключ, OpenAI-совместимый интерфейс |
| **Геодоступность** | Россия | Требуется доступ к OpenRouter (некоторые провайдеры могут блокировать, но с РФ работает) |

**Вывод:**  
Зарубежный вариант на базе OpenRouter с моделью `openai/gpt-oss-120b:free` обеспечивает высокую точность и нулевые затраты на этапе разработки и демонстрации. Российский агент (YandexGPT) рекомендуется для эксплуатации в контуре организации, где важна локализация данных и юридическая прозрачность.

## Руководство пользователя

### 1. Запуск системы
Откройте веб-интерфейс (адрес предоставляется администратором). Вы увидите страницу анализа:

### 2. Загрузка файлов
- **Файл с ответами тестируемых** (обязателен) – JSON, CSV или ZIP-архив, содержащий данные о прохождении тестов. Поддерживаются форматы:
  - JSON: массив объектов с полями UserId, Answers (список ответов с QuestionText, UserAnswer, CorrectAnswer) и Score.
  - CSV: колонки с заголовками UserId, QuestionText, UserAnswer, CorrectAnswer, Score и т.п. Парсер автоматически распознаёт русские и английские названия.
  - ZIP: архив с одним или несколькими CSV/JSON файлами – ответы собираются из всех.
- **Файл с эталонными ответами** (опционально) – если правильные ответы отсутствуют в основном файле, можно загрузить их отдельно. Поддерживаются те же форматы.

### 3. Выбор варианта ИИ-агента
- «Российские нейросети» – будет использован YandexGPT.
- «Зарубежные нейросети» – используется OpenRouter (DeepSeek/Qwen).

### 4. Запуск анализа
Нажмите кнопку «Запустить анализ». Появится индикатор выполнения. Дождитесь завершения (обычно 10–30 секунд в зависимости от объёма данных).

### 5. Интерпретация результатов
После окончания отображается сводка:
- Всего вопросов, количество тестируемых, средний процент правильных ответов, количество критических вопросов.

Ниже кнопки для скачивания JSON и Excel.  
Красный блок «Критические вопросы» показывает формулировки, на которые правильных ответов меньше порога (по умолчанию 50%), а также автоматические рекомендации.

### 6. Экспорт
- **JSON** – полная структура `ReportData` (можно загрузить в другую систему).
- **Excel** – отчёт с подсветкой: красный фон для критических вопросов, жёлтый – для вопросов с пустыми ответами, отдельный лист с рекомендациями.

## Руководство разработчика

### Структура решения

```
TestAInspector.sln
├── Entities/              – сущности, enum, общие модели
├── Parsing/           – интерфейсы и реализация парсеров
├── Validation/        – валидация и предотсев
├── Analysis/          – батчинг, вызов агентов, сбор статистики
├── Agent.Contracts/   – ILlmClient, IPromptProvider, IResponseParser
├── Agent.YandexGPT/      – клиент для YandexGPT
├── Agent.OpenAI/    – OpenAI-совместимый клиент (DeepSeek/OpenRouter)
├── Reporting/         – IReportExporter, Excel-экспортёр
├── Services/          – оркестратор
├── Api/               – ASP.NET Core Web API
└── Web/               – Blazor Server UI
```

### Настройка окружения

1. Клонируйте репозиторий.
2. В проекте `Api/appsettings.json` задайте:
   ```json
   "YandexGPT": { "ApiKey": "...", "FolderId": "..." },
   "ForeignLLM": {
     "BaseUrl": "https://openrouter.ai/api/v1/",
     "RequestUri": "chat/completions",
     "ApiKey": "sk-or-v1-...",
     "Model": "openai/gpt-oss-120b:free"
   }
   ```
3. В `Web/appsettings.json` укажите `ApiBaseUrl` (по умолчанию https://localhost:5001).

### Запуск через CLI
```bash
# API
cd Api
dotnet run

# Web
cd Web
dotnet run
```
Оба проекта должны быть запущены одновременно.

### Добавление нового LLM-агента
1. Реализуйте `ILlmClient` в новом проекте.
2. Зарегистрируйте его через `TryAddEnumerable` в `Program.cs`.
3. При необходимости обновите фабрику `LlmClientFactory`.

    }

### Структура Excel
- Лист «Анализ тестов»: сводка, таблица с детализацией, блок критических замечаний, блок рекомендаций.
- Условное форматирование:  
  - красный фон строки – критический вопрос;  
  - жёлтая заливка ячейки «Пустых» – есть пустые ответы.

### Глоссарий
- **Критический вопрос** – задание, для которого процент правильных ответов ниже порога (по умолчанию 50%). Требует пересмотра формулировки или обучающего материала.
- **ExactMatch** – ответ пользователя после нормализации полностью совпадает с эталоном. Не требует анализа ИИ.
- **Empty** – ответ пользователя пуст или состоит из пробелов.
- **NeedAnalysis** – ответ требует оценки ИИ.
- **Verdict** – вердикт: correct (правильный), partial (частично правильный), incorrect (неправильный).
